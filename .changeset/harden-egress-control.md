Document `network` as the first-class egress-control lever for the Docker and Podman providers, so a subverted agent can be prevented from exfiltrating tokens/source while staying functional. The default posture is **open** — with `network` omitted the container uses the default bridge network and reaches `api.anthropic.com`, git hosts, and registries out of the box — because the agent calls `api.anthropic.com` directly and a blanket blackout would kill the agent itself. Restriction is opt-in and documented: route the container through an internal network plus a filtering forward-proxy that allowlists only the agent's real endpoints (recommended for untrusted work), or use `network: "none"` for the fully-offline degenerate case (no model calls, installs, or remote git). The default-open decision and rationale are recorded in ADR 0021, the README gains an "Egress control" section with the allowlist-proxy recipe, and the emitted `--network` run-line flags are test-asserted for the omitted, custom-string, array, and `"none"` modes. No behavior change to existing runs — the `--network` mechanism already existed; this is documentation, a decision record, and tests.
